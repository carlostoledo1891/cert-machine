# Re-run any decided claim

> Generated by `tools/build-report-rerun.js` — the same build as [/reports/rerun.html](https://carlostoledo.co/reports/rerun.html). Do not edit; edit `corpus/rerun-kit.json`.

Every row of the claims register (`certs/claims-ledger.json`, 131 decided rows) is derived from a record, and every record is re-derivable from this repository. 25 records; 23 re-derive with one command; 7 carry a verifier in the Python standard library with no engine code; 1 carry a second implementation. 1 independent rerun recorded (1 with no code of ours).

## The protocol

1. **Pick a record** from the table. Hash the file you cloned (`shasum -a 256 <record>`); the table gives the hash at the build that wrote this file.
2. **Run one line.** The verifier column is the cheapest and the most independent of the engine: one Python file, standard library only. The re-derive column runs the tool that wrote the record (`--check` re-derives, compares and writes nothing). The second column is the same decision by another program.
3. **Or write your own.** Take the claim as printed on the record's page, decide it with whatever you already trust, and report what you obtained.
4. **Report it:** [a rerun report](https://github.com/carlostoledo1891/cert-machine/issues/new?template=rerun.yml) — the record, how (own code / detached verifier / full re-derivation), the verdict obtained, the sha256 printed, where it ran, the name to record. It is added to `corpus/external-reruns.json` and appears on the page at the next build.

The verifiers shrink the engine, the second implementations shrink the verifiers, and only the registry above shrinks the last item.
