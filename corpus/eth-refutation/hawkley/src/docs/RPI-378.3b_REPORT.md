## The construction (`Simulation/Machine.lean`)

`toTM2 M : TM2ComputableAux Bool Bool`, with input and output alphabets `Bool` via `Equiv.refl`.

| Component | Choice |
|---|---|
| Stacks `K` | `Stk (M.tapes+1)`: `inp`, `out`, and `left i`, `right i` for each tape `i` |
| Alphabets `Γ` | `Bool` for `inp`, `out`; `Fin (M.extraSymbols+3)` (M's symbols, blank `0`) for work stacks; all finite (`finite_Γ`) |
| Labels `Λ` | `load1`, `load2`, `sim`, `clean` |
| State `σ` | `Var M`: control state `q`, scan buffer `Fin (M.tapes+1) → Sym`, scratch `tmp`, `flag` |
| Initial state | `Var.init M = ⟨M.initial, 0, 0, false⟩`, restored before halting |

**Tape representation.** Tape `i` with contents `f : ℤ → Sym` and head `h` is held by
`R = right i` and `L = left i` with

```lean
def Rep (f : ℤ → Sym M) (h : ℤ) (L R : List (Sym M)) : Prop :=
  (∀ j : ℕ, f (h + j) = R.getD j blank) ∧ (∀ j : ℕ, f (h - 1 - j) = L.getD j blank)
```

so the scanned cell is the top of `right i`, and the lists may stop before the trailing blanks.

**One step of `M` in one Mathlib step.** A Mathlib step runs a whole statement. The `sim`
statement branches on whether `q` is an output state; otherwise it peeks the top of every
`right i` into `scan`, then for each tape pops `right i` and, by the move `(w, mv)` that
`M.transition q scan` gives for that tape:

| move | new `left i` | new `right i` |
|---|---|---|
| stay | `L` | `w :: R.tail` |
| right | `w :: L` | `R.tail` |
| left | `L.tail` | `L.getD 0 blank :: w :: R.tail` |

then sets `q` to the next control state and clears the buffers.

## Invariants and proof structure

| Lemma | File | Content |
|---|---|---|
| `rep_step` | `Steps.lean` | writing `w` at the head and moving by `mv` preserves `Rep` (the transition-preservation lemma) |
| `tape_length` | `Steps.lean` | one step adds at most 2 symbols to a tape's two stacks |
| `stepAux_peekAll` | `Steps.lean` | after the peeks, `scan j` is the top of `right j` |
| `stepAux_writeOne`, `stepAux_writeAll` | `Steps.lean` | per-tape stack effects as above; the next control state is unaffected |
| `stepAux_popAll` | `Steps.lean` | one pop per work stack; `flag` records whether any stack was nonempty |
| `load1_spec`, `load2_spec` | `Run.lean` | initialization: the input goes `inp → left 0` (reversed) `→ right 0` (in order, as `inputSymbol`s), `|x| + 1` steps each |
| `SimInv`, `sim_step` | `Run.lean` | configuration correspondence: `inp`, `out` empty and `Rep` on every tape; carried from `c` to `step M c` in one Mathlib step |
| `simInv_init` | `Run.lean` | the loaded stacks represent `initialConfiguration M x` |
| `sim_to_clean` | `Run.lean` | at an output state, one step hands over to `clean` |
| `clean_spec` | `Run.lean` | cleanup: with work stacks of length `≤ m`, halting within `m + 1` steps at `⟨none, Var.init M, outStk b⟩` (output stack `[b]`, all others empty, state reset) |
| `initList_eq`, `haltList_eq` | `Run.lean` | these are exactly Mathlib's `initList` and `haltList` |
| `run_stable` | `Run.lean` | after the first output time `s₀`, `run` is constant, so the emitted bit is the bit at `s₀` |

**Step count.** `(|x|+1) + (|x|+1) + s₀ + 1 + k`, with `k ≤ |x| + 2 s₀ + 1` and `s₀ ≤ s`, so
at most `3|x| + 3 s₀ + 4 ≤ 4 (|x| + s + 1)`.
