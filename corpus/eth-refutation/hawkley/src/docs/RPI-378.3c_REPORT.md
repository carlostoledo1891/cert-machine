## The requested points

1. **Exact output.** `conv_encClauses`: on Anthropic's word for any formula with clauses of at
   most three literals, `conv` returns exactly `encodeFormula (toFormula φ)`.
2. **Satisfiability.** `satisfiable_toFormula_iff` (Patch 1) gives
   `(toFormula φ).Satisfiable ↔ MainResults.Satisfiable φ` on 3-CNFs, and H2 transfers the
   emitted bit `b` unchanged from `M` on `encodeFormula (toFormula φ)` to `M.preprocess` on
   `encClauses 3 φ`; `inTime_of_not_positiveRateETH` (Patch 1) combines the two.
3. **Polynomial time.** `convProgram` is a `PolyProgram`: an `FCode`, its exact run
   `BEval code (treeEncode x) (time x) (treeEncode (conv x))`, and
   `time x ≤ coefficient · (size(treeEncode x) + 1)^degree`.
4. **Uniform degree.** `converterDegree` mentions only `convProgram.degree` and ParityLifts'
   `preprocessingDegree`; neither depends on the downstream machine. Only the constant
   `C_M · (A + 1)^preprocessingDegree` depends on `M`.
5. **Composition.** `converterHypothesis_proved` instantiates `Machine.preprocess_run` with
   `convProgram.program.code` and bounds `B + |x| + s + 1 ≤ (A + 1)(|x| + s + 1)^(degree+1)`,
   where `A = coefficient · 5^degree` (from `size(treeEncode x) ≤ 4|x| + 1`; `compose_bound`).

## How the converter reads Anthropic's word

`encClauses 3 φ = 1ⁿ 0 · chunk(C₁) ⋯ chunk(C_m)`, each chunk three slots of `w = ⌊log₂ 2n⌋ + 1`
bits, lowest bit first, slot value `0` (empty) or `2i + 1 + b` (literal `xᵢ` if `b`, `¬xᵢ`
otherwise). `conv` (`Converter/Spec.lean`):

| Step | Function | Correctness lemma |
|---|---|---|
| `n` = leading `true`s | `truePrefix` | `truePrefix_replicate` |
| body after `1ⁿ0` | `drop (n+1)` | `drop_header` |
| slot width | `wOf n` = bit length of `2n` (or `1`) | `wOf_eq : wOf n = log₂(2n) + 1` |
| cut into clause chunks of `3w` bits | `chunks` (fold carrying `3w`) | `chunks_flatten` |
| nonzero slots of a chunk, in order | `pieces`, `sel` | `pieces_clauseBits`, `sel_slotBits_none/some` |
| literal of slot `v = 2i+1+b` | `b = ¬ bit₀(v)`, `i = val(bits₁…) − b` | `litBits_slotBits` |
| slot value | `capVal`: fold `acc ↦ min cap (2acc + bit)`, cap `2n+2` | `capVal_eq`, `valBits_testBits` |
| ParityLifts clause | `encodeNat len ++ ⋯ (encodeNat i ++ [b])` | `clauseOut_clauseBits` |
| ParityLifts formula | `encodeNat n ++ encodeNat m ++ flatten` | `conv_encClauses` |

**Why a capped reading.** Numbers in ParityLifts tree programs are unary (`numTree`, size
`2v+1`). A `w`-bit slot read naively can reach `2^w`, exponential in the input on arbitrary
words, and every `PolyProgram` must be polynomial on **all** inputs. Capping each step at
`2n + 2` keeps every intermediate value polynomial everywhere; on Anthropic's words every slot
value, and half of it, stays below the cap (`slot_lt`, `lt_two_pow_wOf`), so the reading is exact
there.

**Why the literal decomposition.** `v = 2i + 1 + b` gives `bit₀(v) = ¬b` and `⌊v/2⌋ = i + b`, so
`i` comes from the remaining bits by one subtraction, with no division program.

## The tree program (`Converter/Program.lean`)

Built only from ParityLifts programs in the `SATChoice` closure: `truePrefix`, `drop`, `take`,
`splitAt`, `head`, `tail`, `null`, `cons`, `natAdd`, `natSub`, `natMin`, `natSucc`, `natZero`,
`natBits`, `length`, `encodeNat`, `append`, `reverse`, `any`, `not`, `ite`, `pair`, `comp`,
`mapWith`, `foldlGrowing`, `foldlBounded`. Three new fold obligations:

| Program | Fold | Growth obligation |
|---|---|---|
| `capValProgram` | `foldlBounded 2 1` | `fold_capStep`: the accumulator stays `≤ max acc cap`, the cap is carried unchanged |
| `flattenProgram` | `foldlGrowing 1 1` | `size(acc ++ a) ≤ size(acc) + size(a) + 1` |
| `chunksProgram` | `foldlGrowing 2 0` | `chunkStep_size`: one chunk moved from `rest` to the accumulator adds two tree nodes |

Each assembled program is matched to the specification by `PolyProgram.congr` with a
definitional (`rfl`) or case-split proof.
