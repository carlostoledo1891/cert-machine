# The second reader (claimbox version 3, 2026-10-20) — the blind reading, kept

`claims/` holds the ten objects of a BLIND SECOND READING of the registry-queue claims, exactly as the second reader
wrote them: an AI agent (Claude) given SCHEMA.md, check.py, the ten claim sentences and the corpus folders, forbidden to
open the first reader's objects (instruments/claimbox/claims/), every earlier report, HANDOFF, the yield files, notes
and git, and told to use the version-1 features only. A first attempt earlier the same day wrote its objects to the
session's scratch folder and lost them when the session ended; its report agreed with the first reading on every
decision-bearing choice it mentioned, and this second attempt was made INTO the repository so that it could not be lost.
The comparison is `instruments/claimbox/concord.py` → `certs/claimbox-concord.json`, re-derived by the battery.

## The result

| | claims |
|---|---|
| the same checker outcome (word, kind, decisions) | 9 of 10 |

The one decision-bearing difference is structural, not a different number: for C_86 the first reader wrote two
predicates (a "holds" for the six exact conditions E1–E5 plus the bar inequality), the second reader one (the bar
inequality, with the conditions inside the named function's definition). Same bar, same relation, same record, same
verdict; the checker composes two CERTIFIED into one for the first and reads one for the second, and the concord's
positional rule counts that as a difference. A finding about the format, not about the claim: two encodings of one
claim are both admitted, and version 4 needs a canonical form (one inequality per bar, exact conditions as hypotheses
or as a single "holds") so that the concord compares substance.

The declared differences that matter: the COUNTS. The second reader decoded every count from the pinned files
(65,536; 65,536; 114,688; 3,584; 6,148; 3,584; 300; C_86 1,200 cells of which 629 carry mass; C_82 38 = 7 + 31
factors; Épi 13 = 6 + 7); the first reader declared 629 for C_86 and GUESSED 32 and 9 for the two C_82 objects. The
first reader's objects are kept as they were, because they are the measurement's input; the decoded counts are the
right ones and the yield measurement's caveat "count declared, not decoded" is what version 3's typed data block
removes for the primitive class. The k3072 finding (the claimant's eleven-digit print is below the certificate's
exact value by 3.0e-14) was made independently by both readers.
