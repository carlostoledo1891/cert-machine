# 2026-08-24 — hunt `newman-mu` opened, and what the occupancy read cost and saved

Append-only. Every number below was printed by a command run this session.

## The design changed twice before a campaign fired, both times because of a read

**First framing (from `sin-mfg/research/probes/problem-scout/NEXT_TRACKS_2026-08-20.md`):**
*"Boyd (1986) conjectured μ(n) > 1 for all n ≥ 6 — open at n = 6. A SINGLE 6-term Newman
polynomial with certified min modulus > 1 proves the first case, by exhibition."*

A 30-second float scan found six such sets in a box of 32,768. That ease was the warning,
not the result: an open case of a 1986 conjecture does not fall to half a minute of blind
enumeration. Two reads followed, both local, both free:

1. **`sin-mfg/research/probes/mercer-program/BOYD_HUNT_2026-08-20.md`** — Goddard 1992
   p. 319, read at source by that probe: *"In [5] Boyd shows that f(n) > 1 for 6 ≤ n ≤ 16."*
   **μ(6) > 1 is not open.** It has been settled computationally since 1986, and Goddard's
   own exhaustive grid published the six-term witness in 1992.
2. **`sin-mfg/research/probes/PROBES.md`** — the same lab certified it four days ago:
   Rung 1 certified Goddard's `{0,6,9,10,17,24}`; Rung 2 closed his box exactly (142,506
   sets); Rungs 5–7 pushed the n=6 box to exponent 55 (3,478,761 sets) and produced the
   first certified n=7 and n=8 box maxima; Rung 4 certified Hare–Jankauskas' 19-term
   degree-38 witness at min|f| ≥ 2.0181.

**Had the hunt been built on the first framing it would have rebuilt, badly, a result its
own lab finished on 2026-08-20.** The read that prevented it took about ten minutes and
consisted of one `grep` over the source lab. This is the CHARTER's §"Where novelty is
supposed to come from" working exactly as intended, and it is the whole reason the
occupancy read sits at the front here rather than at promotion.

## The bar that survived

`bar(n)² = max{ certified M(A')² : |A'| < n }` — the monotone envelope. A HIT is an n-term
Newman polynomial beating everything achievable with **fewer** terms, which asks whether μ
is strictly increasing at n. Every literature champion is a HIT under it, so the recall
control has five real planted hits rather than invented ones.

`bar(n)` is **computed from pinned witness exponent sets at load**, never transcribed (C50).

## One correction made during the build, recorded because the first version shipped

The first draft certified the cosine sum and then computed `|f|² = n + 2·[lo,hi]` in
interval arithmetic. Sound, and **~30× looser** than necessary: 1.6e-14 wide against
sin-mfg's 5.2e-16 on the HJ witness, because two extra outward roundings landed on a
quantity the certifier could produce directly. Folding the constant into the BigInt
polynomial (`G = n·T₀ + 2·Σ mᵈ Tᵈ`) removed both roundings and reproduced their enclosure
exactly. The looser version was correct; it was just paying for nothing.

## A defect of mine, caught by the board

The first run declared no `canonicalKey`, so the machine used its default and boarded **six
entries for three objects** — the permutation-duplicate defect the machine's Phase 3 canonical
key exists to prevent (sin-mfg's own retro §2f records 12 of 50 entries lost the same way).
**The omission was ours, not the machine's**: the facility was there and undeclared.

Fixed by declaring `canonicalKey` (lexicographically smaller of the set and its reversal,
after gcd reduction) and `regionOf` = term count. The pre-fix board was **archived, not
deleted**, to `experiments/board-prefix-2026-08-24.json` — it is derived state, fully
reconstructible from the chained run records, and the records themselves are untouched.

## What is NOT established

- **No claim is minted.** No literature gate has run on anything here.
- The n=6 landscape is **occupied and certified by sin-mfg**; this hunt reproduces it in a
  different parameterisation (gaps ≤ 8 rather than exponents ≤ 30/55) and claims nothing new
  from it. The reproduction's value is that it validates a new adapter against a known answer.
- **The frontier is 10 ≤ n ≤ 18**, where nothing is certified by anyone located, and where
  the shipped generators cannot reach — they read `minItems` as a fixed length and so search
  n = 6 only. An instance-local generator is the next build.
- HJ's exclusion of degrees ≤ 40 (their 94.6-hour double-precision filter) is **uncertified
  by them and by us**, and is a separate front.

## Campaign 3 — the frontier front, opened

`hunts/newman-mu/gen-terms.js`: an instance-local generator that varies the TERM COUNT,
because the shipped `enum`/`evolve`/`searcher` all read `minItems` as a fixed vector length
and therefore search n = 6 and nothing else. Three moves — **extend** a boarded champion by
one term (the move that climbs the axis the record lives on), **perturb** one gap, and
**seed** from the near-arithmetic-with-outliers family every known champion belongs to, with
a uniform seed as its own control.

Validated as a pure function before it ran: 400 proposals, **0 schema violations**,
term counts 6…18 covered, all three move types firing. Then inside the funnel's vm fence:
60 candidates, 3 screen passes, 3 certified HIT, 0 new admissions (already boarded).

**Stated so the session summary is not misread:** the forced enum baseline *cannot leave
n = 6* and this generator can, so that pairing is not a like-for-like engine duel. The
asymmetry is real, it is the reason the generator exists, and it is recorded rather than
quietly enjoyed.

## Campaign 3 (v1) — the generator measured itself failing

3000 candidates, 152 certified HITs, **0 new board admissions**, every HIT one of three n=6
gap vectors already boarded. The board field says it in one word, 152 times:
`canonical-duplicate`. **Without the `canonicalKey` fix made earlier the same day, this run
would have reported 152 admissions and read as a triumph.**

The mechanism, from the records rather than from a guess: the board held only n=6 objects, so
leaderboard-driven moves orbited n=6; `extend` produced **n=7 1390 times and no other term
count ever**, because nothing at n=7 clears bar(7)=1.0653, so no n=7 champion was ever
boarded, so extend could never reach n=8. **A ratchet with no pawl.** Best score at n ≥ 10:
≈ −1.75, i.e. sampled min|f|² ≈ 0.1 against a bar of 1.856.

## Campaign 3 (v2) — anchors as priors, and the shrink move

Rebuilt from that record: the known champions seed mutation directly (never emitted
unchanged), and a **shrink** move removes a term — which on HJ's 19-term witness states the
hunt's question as a move: *can 18 terms do what 19 does?* v1 had no move that could ask it.

`battery.js` gained two checks, and **one failed on its first run**: 23 of 1500 proposals came
back as an *unmutated anchor*, because clamping at the gap boundary made a perturbation a
silent no-op (gap 1 stepped down → 0 → clamped back to 1). An anchor arriving on the board
wearing our seed is indistinguishable from a find. Fixed by reflecting off the boundary plus
a total backstop. Battery **35 pass, 0 fail**.

Result: 4000 candidates, **0 screen passes, 0 hits** — and the frontier gap collapsed:

| | v1 best score at n ≥ 10 | v2 best score at n ≥ 10 |
|---|---|---|
| | −1.75 | **−0.006** (n=18) |

a factor of ~290, entirely from the shrink move. The near-miss is HJ minus one exponent.
Zero hits is the honest outcome and it is not the interesting part; the gap is.

## The subset census — a complete certified answer, and one certified enclosure above the bar

The near-miss was close enough that the question stopped being a search and became a
**census**: HJ has 19 exponents, so there are only C(19,k) subsets of each size and every one
can be certified exactly. `hunts/newman-mu/subsets-hj.js`.

```
n = 18  (drop 1)   19 distinct subsets, 0 REFUSED
   best min|f| in [1.3596538405790453, 1.3596538405790457]   removing {35}
   bar(18) = Boyd 1.36237…            gap −7.402110e-3  (below)
   0 of 19 clear the bar

n = 17  (drop 2)   171 distinct subsets, 0 REFUSED
   best min|f| in [1.4141441147942588, 1.4141441147942593]   removing {16,22}
   bar(17) = Boyd 1.36237…            gap +1.437429e-1  *** ABOVE THE BAR ***
   1 of 171 clears the bar
```

**Verified on three independent paths** before being written down: the 3-path
`recheckNewman` (structure + exact rational spot values from an independent polynomial
assembly + dense direct sampling that forms no differences), a K=2²² direct sample landing
inside the enclosure, and the exact integer bound |f(−1)|² = 9. Enclosure width 2.2e-16.

**A structural oddity worth the ink: it is not monotone in the term count.** Dropping *two*
exponents (n=17, min|f|² = 1.99980) beats dropping *one* (n=18, 1.84866). Putting either 16
or 22 back *lowers* the minimum. More terms is not better.

**A near-coincidence flagged so nobody trips on it:** min|f|² = 1.9998035774, which is
2.0e-4 **below** 2, and min|f| = 1.4141441148 against √2 = 1.4142135624 — they differ at the
fourth decimal. It is near, and it is not equal.

### What this is, stated narrowly

A 17-term Newman polynomial with certified min|f| ≥ 1.4141441147942588, i.e. **μ(17) ≥
1.41414 in the terms convention**, obtained by deleting two exponents from a published
witness. The census over all 171 distinct 17-term subsets is complete, so "the best 17-term
subset of HJ's witness" is earned rather than asserted.

### What it is NOT

- **Not a new object.** It is a two-element deletion from Hare–Jankauskas' published set.
- **Not known to be new as a value.** Boyd tabulated 1..21 by *degree*; term-indexed μ(n)
  for 10 ≤ n ≤ 18 was not located by the scout, which is a failed search, not a negative.
  **No literature gate has run.**
- **Not a tripwire.** min|f|² = 1.99980 < 4; the min|f| ≥ 2 record stands at HJ's 19 terms.

### A design flaw this exposed in my own target

`barSq(n)` is computed from a **static** anchor list, so the envelope does not learn. The
census just produced a certified 17-term value of 1.99980 (as min|f|²), which means the
honest `bar(18)` is no longer Boyd's 1.85606 but 1.99980 — and under the corrected envelope
the n=18 row above is further below its bar, not nearer. **The census made its own earlier row
stale, and the target has no mechanism that notices.** Recorded rather than quietly patched:
adopting a new anchor is a decision about what counts as certified, and it is not one a
target file should take on its own while a campaign is running.

## A machine limitation found by using it, NOT patched

The `hj-subsets` run satisfies every substantive condition the machine sets for a
completeness certificate — box exhausted (`generator exhausted`), `rejectAuditRate` 1, every
reject certified, `0 REFUSED`, `0 schemaInvalid` — and still emitted the downgrade
`best known to this search`.

The reason, read in `funnel.js` rather than guessed:

```js
if (gen.name === 'enum' && generatorDone && rejectAuditRate >= 1 && ...)
```

**The gate is keyed on the generator's NAME, not on the property.** Any exhaustive
generator that is not literally called `enum` is refused a certificate it has earned. That
is a check refusing a FACT about the run on the basis of an identity — the exact distinction
`CONSTITUTION.md` draws between refusing a fact and refusing a direction, landing on the
wrong side.

**Not patched, deliberately.** Two reasons: renaming our generator to `enum` would be gaming
a check rather than fixing it, and changing the machine's claim semantics is a doctrine-level
decision that should not happen silently inside a campaign. `make drift` still reads
`39 unchanged · 0 source moved · 0 local edited · 0 source gone`. **Owner's call**; the fix
is one line — test the property, not the name.
