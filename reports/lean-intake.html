Does an AI’s Lean proof prove the right statement? One command to check

A Lean proof can be correct and still prove the wrong thing. Lean’s kernels check the proof; this tool checks the statement, with exact tests instead of a reader’s opinion. Two AI-written refutations of Erdős problems, waiting on Google DeepMind’s list of open problems, went through it.

The mathematics is the claimants’ (Declan Gessel’s, with OpenAI’s GPT-6 Astra, for both refutations); the statements are Google DeepMind’s. This page checks their proofs against those statements. The tool is mine, built with Claude (Anthropic).

What it does not decide

  • Whether the formal statement is the problem. That stays a reading; the small cases are evidence, not proof.
  • “The same” means the same after unfolding definitions. Statements equivalent only by an argument are refused (all 3 planted ones were).
  • Small cases compare true and false. A change that never flips an answer there is invisible to them.
  • Some statements have no small cases. #786(i) is about densities of infinite sets: refused there, as planned.
  • Four of Lean 4.35’s bundled checkers were not run. Both claims are on Lean 4.33.1; leanchecker-paranoid, lean4lean, con-leche, con-ron come later.
does the check work?

Every planted test came out as it should

Each run tests the check itself. Wrong versions of the statement are planted (a dropped hypothesis, a changed constant, a shifted interval) and must be refused; rewordings of the same statement must be accepted; broken copies of the proof must be caught. One square per test; hover for what it was.

Erdős #488

DeepMind’s statement against Erdős’s sentence

Erdős asked whether, for a finite set A and B the numbers with a divisor in A, |B ∩ [1,m]|/m < 2|B ∩ [1,n]|/n always holds for m > n ≥ max(A). Gessel’s proof refutes DeepMind’s Lean version of it; this run reached the same verdicts as a separate hand-built check of 6 November.

Then the new check: Lean evaluated DeepMind’s statement part by part on 3,024 small cases (the kernel confirmed every value), and a program written from Erdős’s sentence alone evaluated the same cases.

Erdős #786(i)

A claim the tool had not seen

Part (i) asks whether some set of density above 1 − ε has all its equal products of equal length. Gessel’s refutation (pull request #5299, open since 6 September) states its own versions of the two definitions it needs. The kernel accepts it against DeepMind’s declaration as it stands today, so the definitions match.

It also turned up one thing for the pull request: DeepMind reworded this statement on 14 October, so the change no longer applies and GitHub reports a conflict. The proof still refutes the current statement.

what I got wrong

Four corrections, made in the open

  • #488: a “wrong” statement was the same. Counting from 0 changes nothing, since 0 is never counted; the kernel saw it. My label was wrong (14 of 15 as first written).
  • #488: the small cases found more than I expected. The 20 cases above, all explained.
  • #488: one planted statement was invisible to the small cases. Counting from 2 changes counts, never answers: the limit, measured.
  • #786(i): a defect in the tool. Fixed and re-run; then 12 of 12 came out as written.

Each spec was committed before its run, and each correction is a dated amendment beside the first outcome.

Re-run it

  • The verdicts. node tools/lean-intake.js record <id> --check re-derives each record from its run’s logs in corpus/lean-intake.
  • The runs. node tools/lean-intake.js run <id> fetches the pins and repeats every step (about 6 GB of Mathlib per claim).
  • The rules. corpus/lean-intake/erdos-488/spec.json and corpus/lean-intake/erdos-786i/spec.json, with their dated amendments; Erdős’s sentence as a program: instruments/intake/erdos-488.js.
