A Lean release on RH and GRH for Dirichlet L-functions, checked in the open

On 25 November 2026 a Lean 4 formalization of the Riemann Hypothesis and of GRH for Dirichlet L-functions was released in two editions, a readable one of about 300,000 lines and a compact one of about 76,000. The proof is Levent Alpöge’s, with Claude, as its README says; the check is ours. This page checks what a machine can check, by rules sealed before any run: whether Lean, and two kernels written apart from it, accept proofs of its five stated theorems from the three standard axioms.

Read the release, at the commit pinned for this check, and the pre-registration, sealed before any run. Every row has a verdict; this build reads the records up to 03:05 UTC on 26 November 2026. Nothing on it is refereed; its change log at the foot says what changed.

gaps and limits

What this check does not establish, before the results

before any result
  • The judge’s sandbox is partial on this machine. The host’s kernel offers Landlock ABI v4, and landrun, the sandbox Comparator calls, warns at every start: “kernel supports Landlock ABI v4, so these default restrictions are not enforced: device ioctl (ABI v5), pathname UNIX socket connections (ABI v9), UDP bind/connect/send (ABI v10), abstract UNIX socket and signal scoping (ABI v6)”. Comparator also asks for a systemd guard against UNIX sockets, which cannot run in a container (amendment A3); the machine has no systemd manager. The sockets a sandboxed process could have reached were recorded before each judge run.
  • con-leche refused the added axiom as an unsupported feature, not as an error. Its line for control C1 is “not implemented yet: non-standard axiom (CertMachine.plantedAxiomC1)” (exit 2). It is a refusal, and Comparator refused the same control by name, but con-leche did not judge that proof; it declined to read it.
  • nanoda printed one error of its own printer. Its line is “Checked 222117 declarations with no typechecker errors, 1 pretty printer errors: [ "Unable to print axioms" ]”: a failure to print the list of axioms, with no typechecker error. The axioms are checked by row A1 and by Comparator, not by this printout.
  • No person read the mathematics. The rows check what a machine can check: that Lean and two kernels written apart from it accept the proofs, from the three standard axioms, of the five theorems as stated. Lean, Mathlib and the axioms propext, Classical.choice and Quot.sound are trusted. Nothing here says that RH or GRH hold beyond that.
  • What the statements mean is carried from the earlier lane, not read again. The release’s statement file is byte for byte the one of Alpöge’s earlier release, whose statements our earlier lane read against the textbooks; that reading is carried over, and only the textbook bridge (CHAR) was re-run, because Mathlib moved.
  • The authors’ own run of the judge used a stand-in for its sandbox. Their README says Comparator accepted the proofs “with a stand-in for its sandbox and ulimit -s unlimited”. Rows S1 and E1 run it in its own sandbox, partial as said above; S2 runs it on their own statement file.
  • The script that runs the steps changed after its seal. Amendment A3 sealed the runner with the other instruments. It was changed twice before the run whose results stand: the order of the steps set to the one A3 fixes, and the install of GNU time after a start that ran nothing (“ended at setup, exit 127: the image has no /usr/bin/time; nothing ran”). The script the run used is named in the pod’s log; both hashes are one click down.
  • The timestamps await a Bitcoin block. The pre-registration and each amendment’s seal are stamped with OpenTimestamps; all 5 proofs are still pending at the calendars, not yet in a block. Until then a stamp shows the calendars’ receipt, not a block.

The pre-registration’s verdict rule, sealed before the run, says the same in its own words; it is quoted in full one click down.

Why this run could finish when the earlier one could not

Comparator, the judge that checks a proof against a statement file of its own, was run on Alpöge’s release of 20 November 2026 by our earlier lane.
