Checking is one pass. Finding more than doubles.

The lock opens only when every switch is on. Checking a setting walks along it once: 2 steps for one switch, 11 for ten, one more for each switch added. Finding the setting by trying them in order, checking each, more than doubles with every switch: 6 steps for one switch, 22,517 for ten.

The lock is simple on purpose, so you can see the answer before the machine does. What it shows is the gap: checking a proposed answer stays cheap while finding one grows out of reach. That gap is why checking someone else’s proof is feasible at all: the checker never has to find the proof, only follow it.

For a whole family of such puzzles, 3-SAT, the Exponential Time Hypothesis (Impagliazzo and Paturi, 1999) says no machine, however clever, can keep the work from multiplying by some fixed factor above one with each switch added. In October 2026 OpenAI and Anthropic each published a Lean proof meant to show that it is false. What I checked in those proofs.

Some questions running cannot answer.

Running a machine can show that it stops: you watch it stop. Running can never show that it does not, because at every step it might still stop at the next one. So a checker that only runs things needs a third answer besides yes and no. On this site that answer is REFUSED: not false, only not decided by this check.

The busy beaver question asks it at full strength: of all the machines with n states that stop on a blank tape, which runs longest? Answering it means settling every other machine of that size, including each one that never stops, and each of those needs an argument, not a run.

Give it a claim.

Each claim names a machine and what it is given. Decide runs it in your tab with a budget of 1,000,000 steps: Certified when the run ends the way the claim says, Refuted when it ends the other way, Refused when the budget runs out first.

  • Some setting of 10 switches opens the lock.

  • The four-state champion stops on a blank tape.
