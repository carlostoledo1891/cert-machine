δ₃ in HOL4: the checker and its blind benchmark, live

δ₃ = 117/2192 (Erdős #1186) rests on five exact certificates. A checker for them is written in HOL4 and runs in HOL4’s kernel, and HOL4 now proves it sound: when it accepts a certificate, the bound that certificate claims holds on its whole region. The 42 lemmas of that proof were a blind benchmark: Claude Opus 5.5 and GPT-6.2 Astra attempted the same 162 statements, some false on purpose, and the HOL4 kernel judged every attempt.

This page is rebuilt from its records; this build reads them up to 19:38 UTC on 25 November 2026. The run ended at 15:09 UTC and was scored at 16:45 UTC, after the answer key was opened. Everything is in the public repository github.com/carlostoledo1891/delta3-hol4. The certificates, and the exact verifier that decided them first, are on the δ₃ report. Nothing here is refereed; the change log is at the foot.

HOL4’s standard ones, the only ones in 159 theories

The checker is a set of HOL4 functions over integers and lists. Given a certificate, it rebuilds the polynomial identity, forms the integer matrix, tests it and returns true or false. Since 17:53 UTC on 25 November 2026, HOL4 also proves what a true answer means.

In plain words

  • The slab theorem. If the slab check accepts a certificate, then the slab polynomial Lθ is at least the bound the certificate claims, at every point of its region.
  • The inner theorem. If the inner check accepts, then L₀ ≥ 0 on its region, and L₀ = 0 only at y = 0.
  • The cover theorem. If the cover check accepts a list of intervals, then every point of [0, 1/2] lies in one of them.
  • Layer 1. The kernel runs each check on its certificate and gets true; put together with the three theorems, that gives one theorem: [0, 1/2] is covered by the five regions; on [0, 1/5], L₀ ≥ 0 with equality only at 0; and on the four slabs, Lθ is at least an exact rational, about 2.7849·10⁻⁴, 3.0355·10⁻⁴, 2.7471·10⁻⁴ and 4.6383·10⁻⁴.

What the kernel certifies

  • No hypothesis, no added axiom. Each of these theorems carries only HOL4’s disk tag (the mark of a theorem read back from a theory file), no axiom tag and no hypothesis. In the 159 theories behind the final theorem, the only axioms are HOL4’s four standard ones. Every lemma theorem they rest on reads back the same way (54 read-backs over the three soundness theories).
  • The checks run in the kernel. HOL4 proves ⊢ check <data> ⇔ T for each certificate: the four slabs in 1.15–1.36 s each, the inner certificate (22,808 forms) in 1.29 s; the same check in JavaScript takes 0.18 s, so the kernel is 6.4 times slower.
  • Forgeries are refused. The battery’s 40 forgeries (37 forged certificates, 3 forged covers): 39 give false in the kernel, and the loader refuses the malformed one before the kernel.
  • A compiled copy. The same checker, compiled by CakeML into a binary, agrees with the kernel on 52 of 52 inputs, at 0.28–0.32 s per certificate. Kernel runs at two HOL4 releases give byte-identical theorems on all 51 inputs that reach the kernel.

What is still data, or not in HOL4

  • The model constants are data. The areas and constants of the extremal colouring, from which Lθ and L₀ are built, are computed by the JavaScript verifier and loaded into HOL4 as data. So the theorems are about Lθ and L₀ built from that data.
  • The step to δ₃ is not in HOL4. The analysis that takes these bounds to δ₃ = 117/2192, and the uniqueness of the extremal colouring, are not in HOL4. Each certificate also lives on its own grid; no theorem here joins them over one point.
  • The witness is untrusted. The Gram factor, the weights and the scale are hints written in floating point. A wrong hint can only turn true into false, so false on a forgery says the check fails with that witness, not that no witness exists.
  • Strictness is tested by strict diagonal dominance, now proved sufficient for positive definiteness, but not necessary; the JavaScript verifier tests leading minors, which is exact. Both accept all five certificates.
  • The trusted base. HOL4’s kernel, including its compute primitive. That primitive is a port of the compute facility proved sound for Candle (O. Abrahamsson, M. O. Myreen, M. Norrish, H. Kanabar, J. Åman Pohjola, J. Automated Reasoning 69(1):7, 2025); the port itself is not proved inside HOL4. The binary adds CakeML’s released compiler binary, the C stubs of its basis library and the link step.

All of it, in public

The checker, the proofs, the certificates, the run’s logs and the answer key are in the repository github.com/carlostoledo1891/delta3-hol4. Its README says what is proved and how each lemma was made. One command, replay.sh, rebuilds it all from the pinned HOL4: from a fresh copy it ended with exit 0 in 1,415 s, with the same 52 kernel verdicts and the three soundness theorems exactly as stated. A workflow runs it on every push: its first run, on GitHub’s own runner with Poly/ML and HOL4 built from scratch, passed in 27 min 39 s (19:07–19:37 UTC).

Related work

The full statement δ₃ = 117/2192 is formalised in Lean by Snively (erdos-1186, v1.0.0, 26 October 2026). Star Fleet Math stated the value, with an exact rational sum-of-squares certificate, by 15 July 2026 (Internet Archive capture 20260715002525). This work is a checker in HOL4 for the certificates; it does not state δ₃ as a HOL4 theorem.

what went wrong

What went wrong during the run, and what was done

Said in plain words, as the records state it. Five were found and acted on while the run was open; the other two after it ended, before the answer key was opened.

  1. 13:41 UTC The judge’s log could be read across the two families.

    The judge writes every attempt of both families to one log. The brief forbade reading the other family’s folder, but not that log. A Claude agent read it; the GPT family was ahead, so a Claude agent reading the log could see GPT outcomes before attempting the same statement.

    Done. At 13:42 UTC the 4 Claude agents then running were told not to read the log or other agents’ results, and to report whether they had, and for which statements. Each later Claude agent gets the same message at its start.

    In the scoring. The blinding audit counts every read of the log, per agent and per statement. The Claude family is scored twice: with all its statements, and without the statements an agent could have seen in the log first.

  2. 13:51 UTC Work from before the run, by an agent that had seen the answer texts, could be read.

    A folder the proving agents were allowed to read still held earlier attempts and proofs written before the run by a Claude agent that built the harness and had read the texts of the true statements. One Claude proving agent used that material for 2 of its statements. Also readable: the first answer key’s statement list, whose lists identify 41 of its 44 planted texts (this run uses the same texts, renumbered), and one accepted proof from before the run.

    Done. At 13:51 UTC all of it (11 folders, the first statement list and the accepted proof) was moved out of the folders the agents may read; a note stands in its place.

    In the scoring. Those 2 statements are marked contaminated for the Claude family, which is reported with and without them. The blinding audit lists every read of the moved material by any agent of either family, with its time; any statement decided after such a read is reported separately.

  3. 13:29 UTC A correct refutation would have stopped the run.

    A refutation proves that a statement’s text, taken alone without its “may use” hypotheses, is false. A decoy whose text is a planted (false) text is true as a whole, because one of its hypotheses is false, yet its text can be refuted. The protocol said that refuting a decoy meant a kernel or judge fault and stopped the run. This was found during the run and written down before the answer key is opened.

    Done. Ruled at 13:29 UTC, before the key is opened: such a refutation is correct. It is reported in its own column, “text refuted”, beside “proved”, and it does not stop the run. A family that refuted such a decoy first can no longer prove it, and the report says so.

    In the scoring. The rule that stops the run stays for a refutation of a true original or of a decoy whose text is true.

  4. 13:47 UTC A planted statement can be true, vacuously.

    A Claude agent found that a planted statement’s “may use” list can name a decoy whose text is false. The planted statement then holds vacuously and has a correct kernel proof, and the gate “zero planted statements proved” would have flagged a correct proof as a fault.

    Done. Ruled at 13:47 UTC, before the key is opened: the gate judges what the kernel judged. Zero “proved” on a statement whose goal is false, and zero “refuted” on a statement whose text is true; either one would mean a kernel or judge fault. A planted statement whose goal holds vacuously is scored in its own class.

    In the scoring. Every statement is classed by the truth of what the kernel was asked to judge, read from the key once it is opened.

  5. 14:06 UTC A sentence in the protocol named one statement and both families’ outcomes on it.

    The text of the 13:29 ruling, added to the protocol file the agents may read, named one statement and how both families had decided it. Both had already decided it, so no attempt on it could change; the sentence could still hint at the role of the statements that share its text.

    Done. At 14:06 UTC the statement and its outcomes were taken out of the protocol file; the case is kept in the private work log.

    In the scoring. The blinding audit counted the reads of the protocol after 13:29 that showed the sentence: 2 by Claude agents, 1 by a GPT session.

  6. 15:29 UTC What the two blinding audits found.

    After the run, a Claude agent read every agent’s tool log (906 Claude tool calls, 973 GPT shell commands). All nine GPT sessions were clean; six of the nine Claude agents were not. It found two reads the agents had not reported: two Claude agents read the whole proof from before the run in the run’s first minutes, and a third read the texts of the first statement list. Nobody read the answer key or the other family’s folder, or ran HOL4 outside the judge.

    Done. A GPT-6.2 agent then audited the same logs on its own (at 16:08 UTC). It agreed on every agent and every read that matters, and differed on the size of three sets (the table below). Scoring uses the union of the two, the stricter reading.

    In the scoring. 23 of the Claude family’s statements are left out of its blind rows: 5 where an agent used or read the material from before the run, and 18 more where an agent could have seen the GPT family’s outcome first. 139 statements remain. The GPT family has none left out.

  7. 16:19 UTC The two readers disagreed on style in 57 scripts.

    Every accepted script was read by two agents, each alone, against a seven-item checklist; no person read them. The Claude reader passed all 307. The GPT-6.2 reader passed 250 and flagged 57 on two style items only: top-level code in the script (55) and two extra standard HOL4 theories (2). Neither reader found a soundness problem.

    Done. Ruled at 16:19 UTC, before the key was opened: a flag on one of those two style items alone, with the other reader passing and no flag on the five other items, does not exclude an attempt. All 57 are listed, with both readers’ reasons, in the scoring report.

Known limits

  • The first answer key, frozen at 22:03 UTC on 24 November, was printed into AI session transcripts on the machine that runs the benchmark. It was replaced before the run by a fresh key, frozen at 10:25 UTC on 25 November and encrypted under a passphrase that one person, Carlos Toledo, holds.
  • The Claude agents that built the harness read the texts of the true statements. The proving agents are other agents; the blinding audits checked what each of them read.
  • Nothing stops an agent from reading a file: the machine does not restrict reads. The blinding rule was checked afterwards, on every agent’s tool log, twice.
  • Agents of the same family may read each other’s scripts. The brief allows it; reuse is reported, not excluded.
  • The decoys remove the signal that used to mark the true statements; weaker signals remain, were measured before the run, and are reported with the results.
  • The judge trusts the files HOL4 writes. A deliberate forgery from inside a build would be stopped only by a text filter on the script and by reading the script, which is why every accepted proof was rebuilt alone and read by two agents.
  • The judge kept running through the pause: 1 Claude Opus 5.5 attempt and 2 GPT-6.2 Astra attempts, already submitted when the agents stopped (11:39 UTC), were judged during it.
  • The blinding audits are agent audits. The first was done by a Claude agent of the same session as the nine Claude provers; the second, by a GPT-6.2 agent, read a work log that already carried the first one’s headline.
  • Each family’s tokens are counted by its own tool (the Agent tool’s report for Claude, Codex’s count for GPT), so the two totals are not one measure.
how the proof was made

How each lemma on the chain was made

The soundness proof is 42 true lemmas, mixed into the run’s 162 statements with false ones and decoys. With the clean-room proofs, no lemma on the chain rests on a contaminated proof.

  • 35 blind, by GPT-6.2 Astra, in the run
  • 3 blind, by Claude Opus 5.5, in the run
  • 1 by Claude in the run, after its agent had seen GPT’s three failed attempts (not counted as blind)
  • 2 clean room, after scoring: a fresh Claude agent that never saw an earlier proof
  • 1 by the builder, after scoring, who had read the key (not blind)
  • The rule. One proof per lemma, each built unchanged and checked to be exactly its judged statement. Where both families had a blind proof, the one judged first was taken; in all, 35 of the 42 proofs on the chain are GPT-6.2’s. Every proof on the chain, the ones made after scoring included, was accepted by the same judge code against the same frozen statements. None of this changes the scores, which count only the run’s attempts.
  • Three blind proofs by Claude. L22 (S027, slab_matrix_shape_sym), L37 (S109, inner_matrix_val) and L40 (S049, inner_check_sound): the only accepted proofs of these lemmas in the run.
  • One proof by Claude, not counted as blind. L12 (S084, add_form_val_y): the only accepted proof in the run, by an agent that had seen the GPT family’s three failed attempts at it first.
  • Two proofs made again, in a clean room. L26 (S040, dd_rows_psd) and L29 (S046, sdd_rows_pd), the diagonal-dominance lemma and its strict form. The run’s only accepted proofs of them were contaminated: built on a proof from before the run, by an agent that had read the key. After scoring, a fresh Claude agent that saw only the public brief, the definitions, the judge and HOL4’s sources proved both, each at its first attempt (both at 18:36 UTC), judged by a copy of the frozen judge; an audit of its tool calls found no read of an earlier proof or of the key. Those proofs are on the chain; the contaminated ones stay in the repository as the run’s record.
  • One proof by the builder. L28 (S149, slab_check_sound): the slab soundness theorem itself, the one true statement neither family proved in its three attempts. The builder, who had read the key, fixed the last step of Claude’s third attempt, and the same judge code accepted it at 16:52 UTC. It is labelled not blind.

how it worked

How the benchmark worked

  • Two model families. Claude Opus 5.5 (claude-opus-5-5), one agent per batch, and GPT-6.2 Astra (gpt-6.2-astra, through the Codex command line), one session per batch.
  • The same statements, the same order. Both families got the same 162 statements about the checker, in the same nine batches of 18, with the same brief and no hints beyond it. The agents were told some statements are false.
  • At most 3 attempts per statement. Proofs and refutations together, per family. A family stops at its first judged outcome on a statement: proved, or refuted (the statement’s text shown false).
  • One judge, the same limits. Every attempt was a complete HOL4 script, built on a rented judge machine with no network, under the same limits for both families: 600 s of wall time, 1,200 s of CPU per process, 6 GB of memory. The kernel’s answer is the outcome: proved, refuted, failed, timeout or refused. HOL4 is pinned at trindemossen-2-v10, Poly/ML at v5.9.2. Every attempt of the run was judged on that one machine, by one version of the judge, against one frozen statement list.
  • A sealed answer key. Which statements are true, planted or decoys was in a key encrypted before the run (frozen 10:25 UTC on 25 November 2026) under a passphrase that one person, Carlos Toledo, holds. He opened it at 16:45 UTC, after the run, the rebuilds, the readers and the audits; it is now public, with its hashes, in the repository.
  • What an agent may not do. Run HOL4 itself (every build goes through the judge), or read the true statements’ texts, the other family’s folder, or any agent’s session transcript. Every agent’s tool log was audited for this after the run, twice.
  • Controls first. 9 of 9 controls, the memory limit and both refutation controls passed on the judge machine before the run.
